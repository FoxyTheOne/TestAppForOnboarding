# Конспект: Firebase в этом приложении

Что такое Firebase, что именно приложение там хранит, как устроен каждый сценарий (регистрация,
вход, выход…), что защищает данные и что остаётся сделать руками в консоли.
Пути файлов – от `app/src/main/java/com/foxynest/testappforonboarding/`.

Правила безопасности разобраны отдельно, подробно: [FIRESTORE_RULES.md](FIRESTORE_RULES.md).

---

## 1. Firebase за две минуты

Firebase – готовый сервер от Google. Свой сервер писать не нужно: приложение напрямую обращается к
сервисам Google.
Здесь используются два сервиса:

| Сервис                    | Что хранит                                                                                                 | Где посмотреть в консоли                     |
|---------------------------|------------------------------------------------------------------------------------------------------------|----------------------------------------------|
| **Authentication** (Auth) | Аккаунты: email, пароль (только хэш, его не видит никто, даже владелец проекта), uid, «почта подтверждена» | Firebase Console → Authentication → Users    |
| **Cloud Firestore**       | Базу данных: по одному документу на пользователя, `users/{uid}`, с анкетой                                 | Firebase Console → Firestore Database → Data |

```
          Телефон                                       Google (Firebase)
 ┌─────────────────────────┐                ┌──────────────────────────────────────┐
 │ DataStore (на устройстве)│                │ Auth                                 │
 │  • анкета                │   вход/выход   │  uid: Xy7…  email: mama@…  ✓ почта   │
 │  • черновик опроса       │ ─────────────▶ │                                      │
 │  • данные для поздравл.  │                │ Firestore                            │
 │  • язык                  │  чтение/запись │  users/Xy7… { username, childName,   │
 │                          │ ─────────────▶ │     childGender, childBirthDate, …}  │
 │ Кэш Firestore            │                │                                      │
 │  (копия своего документа │                │ Правила безопасности (firestore.rules)│
 │   + неотправленные записи)│◀── охранник ──│  «документ Xy7… – только для Xy7…»   │
 └─────────────────────────┘                └──────────────────────────────────────┘
```

Главное, что нужно понять:

- **uid** – постоянный id аккаунта, его выдаёт Auth. Документ в Firestore называется так же, как
  uid. Так документ «принадлежит» аккаунту.
- **Ключ Firebase лежит в каждом APK** (`google-services.json`), и это нормально. Он только говорит,
  *к какому проекту* обращаться, но не даёт прав. Права даёт вход в аккаунт, а проверяют их
  **правила безопасности** на сервере.
- **Без регистрации Firebase не используется.** Незарегистрированный пользователь работает только с
  DataStore на телефоне.

## 2. Где это в коде

```
 Экраны (presentation)      →  Use case-ы (domain)        →  Репозиторий (data)  →  Firebase (data)
 LoginViewModel                 LoginUC                        AuthRepository          FirebaseAuthDataSource
 RegistrationViewModel          RegisterUC                                                 + UserFirestoreMapper
 MainViewModel                  LogoutUC, DeleteAccountUC                                  + UserFirestoreFields
 ProfileViewModel               UpdateFirebaseProfileUC, …
```

| Файл                                                 | Что в нём                                                                             |
|------------------------------------------------------|---------------------------------------------------------------------------------------|
| `data/dataSource/firebase/FirebaseAuthDataSource.kt` | **Единственное место, где есть Firebase.** Все запросы и перевод ошибок в `ErrorType` |
| `data/dataSource/firebase/UserFirestoreMapper.kt`    | Профиль ↔ документ Firestore                                                          |
| `data/dataSource/firebase/UserFirestoreFields.kt`    | Имена полей документа (их нельзя переименовывать просто так)                          |
| `domain/iRepository/IAuthRepository.kt`              | Что domain-у нужно от сервера, без единого типа Firebase                              |
| `domain/use_cases/authUseCases/`                     | Вход, регистрация, выход, удаление, сброс пароля, почта                               |
| `presentation/MainViewModel.kt`                      | Подписка на профиль, выход, удаление, смена почты, «сессия завершена»                 |
| `firestore.rules`                                    | Копия правил безопасности (публикуются в консоли вручную)                             |
| `di/SingletonModule.kt`                              | Откуда берутся `FirebaseAuth` и `FirebaseFirestore`                                   |

## 3. Сценарии по шагам

### Регистрация

Открывается из профиля, после того как опрос уже пройден. Код: `FirebaseAuthDataSource.register`.

1. `createUserWithEmailAndPassword` создаёт аккаунт в Auth, и пользователь сразу считается вошедшим.
2. `set(...)` записывает анкету в `users/{uid}`, `createdAt` ставит сервер.
3. Уходит письмо «подтвердите почту». Подтверждение мягкое: приложением можно пользоваться и без
   него.

Если шаг 2 не удался, например пропала сеть, регистрация всё равно успешна. Иначе повторная попытка
дала бы «email уже занят». Недостающий профиль `MainViewModel` дошлёт сам при следующей загрузке (
`repairFirebaseProfileFromLocalData`).

### Вход

`signInWithEmailAndPassword`. Firebase сам запоминает сессию на устройстве. Пароль при следующих
запусках не нужен, `isLoggedIn()` работает без сети.

### Запуск приложения

`SplashViewModel`: миграция данных, потом проверка «вошёл?» (локально, без сети). Если вошёл,
открывается главная.
Профиль на экраны приносит подписка из `MainViewModel`.

### Загрузка профиля (snapshot-листенер)

`FirebaseAuthDataSource.observeCurrentUser`. Вместо разового «прочитать документ» приложение
**подписывается** на него:

- сначала мгновенно приходит копия из кэша на телефоне (работает и без сети), потом свежая с
  сервера;
- если документ изменили на другом устройстве, изменение придёт само;
- подписка живёт, пока экран на неё смотрит, плюс 5 секунд (`WhileSubscribed`), потом отключается.
  Чтение тарифицируется по количеству документов, поэтому лишние подписки не держим.

### Сохранение анкеты

Происходит, если пройти опрос заново, будучи вошедшим. Код: `updateProfile`.

- `set(..., SetOptions.merge())` обновляет только переданные поля и создаёт документ, если его нет;
- `UpdateFirebaseProfileUC` не отправит неполную анкету: пустое поле перезаписало бы хорошее
  значение пустым.

### Без интернета

Firestore записывает изменения в свой кэш на телефоне и отправляет их сам, когда появится сеть, даже
после перезапуска приложения. Поэтому запись ждёт ответа сервера максимум 10 секунд, а потом
считается принятой.

### Выход

`logout` сначала ждёт, пока уйдут неотправленные изменения. После выхода сервер их уже не примет,
ведь писать
может только вошедший владелец. Если сети нет, приложение не выходит и показывает сообщение. После
успешного
выхода `LogoutUC` стирает анкету на телефоне и отменяет поздравление.

### Удаление аккаунта

Требование Google Play для приложений с регистрацией. Кнопка в профиле, нужен пароль.

1. `reauthenticate` – повторный вход. Firebase требует «свежий» вход для опасных действий: защита от
   чужих рук.
2. Удаляется документ `users/{uid}`. Это делается раньше аккаунта: без аккаунта правила к документу
   не пустят.
3. Удаляется аккаунт в Auth.
4. `DeleteAccountUC` стирает данные на телефоне и отменяет поздравление.

### Смена почты для входа

`updateAuthEmail`: пароль → `reauthenticate` → `verifyBeforeUpdateEmail(новая)`.

- письмо уходит на **новый** адрес, а почта меняется только после перехода по ссылке. Опечатка в
  адресе не заблокирует аккаунт;
- после смены Firebase завершает сессии, и `MainViewModel` замечает «был пользователь – стал null
  без нажатия "Выйти"». Тогда показывается пояснение «войдите с новой почтой»;
- текущая почта при этом может быть и неподтверждённой.

### Подтверждение почты

Письмо уходит при регистрации, повторно – по кнопке в профиле. Человек подтверждает почту в
браузере, а приложение
узнаёт об этом через `reload()`: при каждом открытии профиля и часто в течение 2 минут после
отправки письма.

### «Забыли пароль?»

`sendPasswordResetEmail`. Новый пароль вводится на странице Firebase по ссылке из письма. Приложение
всегда показывает нейтральный текст «если аккаунт есть, письмо придёт»: так нельзя выяснить,
зарегистрирован ли чужой адрес.

## 4. Ошибки

Ошибки Firebase переводятся в `ErrorType` по **типу** исключения, а не по тексту: текст Firebase
может поменять, и он на английском. Перевод – `FirebaseAuthDataSource.toErrorResource`, текст для
экрана – `presentation/common/DomainDisplay.kt`.

| Исключение Firebase                             | ErrorType                                                      | Что увидит человек                                    |
|-------------------------------------------------|----------------------------------------------------------------|-------------------------------------------------------|
| `FirebaseNetworkException`                      | `INTERNET_ERROR`                                               | Нет интернета                                         |
| `FirebaseTooManyRequestsException`              | `TOO_MANY_ATTEMPTS_ERROR`                                      | Слишком много попыток, подождите                      |
| `FirebaseAuthWeakPasswordException`             | `PASSWORD_TOO_WEAK_ERROR`                                      | Слабый пароль                                         |
| `FirebaseAuthUserCollisionException`            | `EMAIL_ALREADY_REGISTERED_ERROR`                               | Почта уже зарегистрирована                            |
| `FirebaseAuthInvalidCredentialsException`       | `EMAIL_FORMAT_ERROR` или «неверные данные» / «неверный пароль» | Зависит от операции                                   |
| `FirebaseAuthInvalidUserException`              | `AUTH_DATA_ERROR`                                              | Неверные данные для входа                             |
| Неотправленные изменения при выходе             | `UNSYNCED_DATA_LOGOUT_ERROR`                                   | Подключитесь к интернету, чтобы не потерять изменения |
| Отказ правил безопасности (`PERMISSION_DENIED`) | `DATA_NOT_SAVED_ERROR`                                         | Данные не сохранены (в Logcat – точная причина)       |

## 5. Ответственность: чего боимся и что на самом деле

| Страх                                 | Что на самом деле                                                                                                                | Что защищает                                                                                  |
|---------------------------------------|----------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------|
| «Ключ API виден в APK – взломают»     | Ключ публичный по замыслу Google, он не даёт прав                                                                                | Правила безопасности; ограничение ключа по пакету и SHA-1 в Google Cloud Console              |
| «Кто-то прочитает чужие данные»       | Читать документ может только вошедший владелец                                                                                   | `allow read: if isOwner(userId)` в `firestore.rules`                                          |
| «Запишут мусор или гигантские данные» | Сервер проверяет каждое поле: имя, тип, длину, формат даты                                                                       | `allowedFields()` и `hasValidValues()` в правилах                                             |
| «Придёт огромный счёт»                | На бесплатном тарифе Spark карта не привязана. При превышении квоты запросы отклоняются до следующего дня, но денег не списывают | Тариф Spark. При переходе на Blaze сразу настроить бюджет и оповещения                        |
| «Пароли утекут»                       | Пароли приложение не хранит и не видит, их хэширует Firebase                                                                     | Firebase Auth                                                                                 |
| «Пользователь потеряет анкету»        | Офлайн-кэш, запись без перетирания пустыми полями, дозапись после сбоя регистрации, выход ждёт синхронизации                     | `awaitWrite`, `isValidData`, `repairFirebaseProfileFromLocalData`, `logout`                   |
| «Удалю базу случайно»                 | Удалить базу можно только в консоли, вручную, с подтверждением                                                                   | По желанию – защита от удаления (delete protection) через Cloud Shell. Правила хранятся в git |
| «Тестовый режим базы»                 | Правила из мастера «на 30 дней» через 30 дней закрывают базу для всех                                                            | Использовать только `firestore.rules` из проекта                                              |

**Персональные данные.** Имя родителя, имя и дата рождения ребёнка – это персональные данные. Отсюда
обязанности:

- политика конфиденциальности (ссылка в Google Play и в приложении);
- удаление аккаунта в приложении (сделано) и веб-страница для удаления (нужна для Google Play, пока
  не сделана);
- форма Data safety в Google Play Console: какие данные собираются и зачем;
- законы о персональных данных есть во многих странах. В первую очередь важны закон страны
  разработчика и законы стран, на которые приложение явно рассчитано (язык, валюта, реклама). Для ЕС
  это GDPR. В России и Казахстане есть требование хранить данные граждан на серверах внутри страны (
  локализация). Для зарубежного разработчика маленького приложения это вопрос риска (в худшем случае
  блокировка в этой стране), а не автоматическое нарушение. Самый надёжный способ снизить любые
  риски – не хранить на сервере лишнего: например, держать данные ребёнка только на телефоне. Перед
  платной версией стоит один раз проконсультироваться с юристом.

## 6. Что делается руками в консоли

Поставьте галочки по мере выполнения.

- [ ] Правила из `firestore.rules` опубликованы: Firebase Console → Firestore Database → Rules
  (порядок и проверка – [FIRESTORE_RULES.md](FIRESTORE_RULES.md), раздел 6)
- [ ] Ключ «Android key» ограничен приложением: Google Cloud Console → APIs & Services →
  Credentials →
  Android key → Application restrictions → Android apps → пакет
  `com.foxynest.testappforonboarding` + SHA-1.
  SHA-1 показывает `.\gradlew signingReport` в терминале Android Studio. Для release-сборки нужен
  отдельный
  SHA-1 ключа подписи, а при публикации через Google Play – ещё и SHA-1 из Play Console → App
  integrity
- [ ] «Browser key» не трогать: им пользуются ссылки из писем (подтверждение почты, сброс пароля)
- [ ] Сервисный аккаунт (странная почта `…@….iam.gserviceaccount.com`) не трогать: это «робот»
  самого Firebase
- [ ] Authentication → Settings → проверить, что включена защита от перебора email (email
  enumeration protection)
- [ ] Позже, в настоящем проекте: App Check, страница удаления аккаунта, политика конфиденциальности
- [ ] В настоящем проекте при создании базы Firestore выбрать расположение в ЕС (например, `eur3` или
    `europe-central2` – Варшава). **Изменить его потом нельзя**, только создать базу заново
- [ ] Принять условия обработки данных (GDPR): Firebase Console → Project settings → General/Privacy →
  Data Processing Terms (в Google Cloud это Data Processing Addendum)
- [ ] По желанию: защита базы от удаления

## 7. Проверка руками на настоящем Firebase

Эти сценарии работают с настоящим сервером, их стоит пройти на тестовом аккаунте.
Удобно держать открытыми консоль (Authentication → Users и Firestore → Data) и Logcat с фильтром
`FirebaseAuthDataSource`.

1. **Регистрация.** В Users появился аккаунт, в Data – документ `users/<uid>` со всеми полями анкеты
   и `createdAt`. Пришло письмо подтверждения.
2. **Без сети.** Включить режим полёта, пройти опрос заново, выключить режим полёта. Через несколько
   секунд
   документ в консоли обновится сам.
3. **Выход без сети.** Изменить анкету в режиме полёта и нажать «Выйти». Появится сообщение про
   неотправленные изменения, выхода не будет.
4. **Подтверждение почты.** Перейти по ссылке из письма и вернуться в приложение. Плашка «почта не
   подтверждена»
   исчезнет.
5. **Забыли пароль.** Пришло письмо, новый пароль задаётся по ссылке, вход с новым паролем работает.
6. **Смена почты.** Пришло письмо на новый адрес. После перехода по ссылке приложение показало
   «сессия завершена»,
   вход по новой почте работает, по старой – нет.
7. **Удаление аккаунта.** С неверным паролем – ошибка под полем, ничего не удалено. С верным – в
   консоли нет
   ни аккаунта, ни документа, приложение вернулось на приветствие.
8. **Чужой документ.** Rules Playground в консоли: чтение `users/abc` от имени `xyz` должно быть
   запрещено.

## 8. Частые вопросы

**Почему профиль виден без интернета?** Snapshot-листенер сначала отдаёт копию из кэша Firestore на
телефоне.

**Где посмотреть данные пользователя?** Firebase Console → Authentication → Users (там uid).
Firestore → Data → `users` → документ с этим uid.

**Что будет, если удалить пользователя в консоли?** Его сессия на телефоне закончится при следующем
обновлении
токена, и приложение покажет «сессия завершена». Документ в Firestore при этом **не** удалится сам:
удаляйте и его.

**Добавляю новое поле в анкету – что не забыть?** Чек-лист
в [FIRESTORE_RULES.md](FIRESTORE_RULES.md), раздел 7.
Главное: сначала правила, потом выпуск приложения.

**Можно ли смотреть чужие анкеты из приложения, например «для админа»?** Сейчас правила этого не
позволяют, и это правильно. Для админских задач используют консоль.
